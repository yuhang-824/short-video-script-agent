# 复盘、用时和下一步

## 最难的问题

难点是把“生成了脚本”与“当前版本确实通过检查”分开。一次压缩或人工编辑后，如果沿用旧时长/批准，会把超时或无依据内容导出为通过结果。本题将草稿摘要绑定两项检查，修改即失效；网页也即时禁用下载，并保护异步校验期间的新编辑。

另一个取舍是只拥有“支持字幕”的原文，却容易产生听起来合理的自动识别或80%效率结论。本原型选保守事实原文和中性文案白名单，降低无依据主张风险，同时明确牺牲开放创意、风格适配和改写自由，不声称通用语义核验。

## 学习与改进

- 用同一工具结果驱动不同后续动作，而不是只演示一条成功链路；正常45秒直接通过，30秒修订，2秒尝试后明确失败。
- 时长应来自分镜文字与停留的计算。把语速改2字/秒后49→35→13，能证明记录会随实际返回改变。
- ID存在不足以证明引用正确，还需对应原文、镜头和主张。保持来源版本和指纹，便于更换资料复验。
- 本机UI增加编辑能力时，也必须重新建立校验边界；人工校验要有独立标记，不能悄悄改写Agent历史。
- 原生工具调用能清晰展示模型与本地职责。其效果仍需真实接口运行来证明，离线策略不能替代。
